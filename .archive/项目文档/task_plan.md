## 九阶段执行流程

### Phase 1: 需求与原则冻结 (Status: pending)
- **输入**: 用户需求文档
- **输出**: 
  - 需求及原则确认单 (成果#1)
  - 十二项待确认事项清单 (T-01 to T-12)
  - 决议要点（待taolun讨论）
- **关键决策**:
  - T-01: 业务分类是7类还是8/9类？
  - T-02: 教师与行政办公是否合并？
  - T-03: 三校区L2模型是否必须相同？
  - T-04: 是否全部重编旧地址？
  - T-08: 网关采用首个/24还是末端/24的.254？
  - T-11: SuperVLAN迁移是否允许直接改父VLAN号？
  - T-12: 物理互联和路由协议边界？

### Phase 2: 现网基线采集 (Status: pending)
- **输入**: 三校区配置文件、VLAN表、资产表
- **输出**:
  - 现网事实基线表 (成果#2)
  - 现网问题清单 (成果#3)
  - 13个配置文件分析报告
- **数据源**:
  - 东/西/南校区核心交换机纯净配置(3个)
  - MobaXterm抓取的当前配置(3个)
  - IP规划表 (xlsx)
  - VLAN表 (docx, xlsx)
  - 点位表 (xlsx)

### Phase 3: 数据清洗与问题分级 (Status: pending)
- **输入**: Phase 2原始数据
- **输出**:
  - 清洗后的规范化数据集
  - P0/P1/P2问题分级表
  - 证据索引（配置文件行号、资产表位置）
- **关键问题识别**:
  - 东校区: 10.11.0.0/16、10.12.0.0/14、10.16.0.0/15 路由所有权问题
  - 服务器区: 10.41.0.0/16 与东校区10.41.12.0/22冲突
  - 南校区: 3210编号冲突
  - 三校区: 命名不统一、编号混乱、业务边界不清

### Phase 4: IPAM源数据表建立 (Status: pending)
- **输入**: Phase 3规范化数据 + 设计编码规则(第四章)
- **输出**: 
  - 唯一权威IPAM源数据表 (成果#4)
  - 编码规则应用说明
- **IPAM记录字段** (每条必填):
  - 对象ID, 校区, 业务, 位置/楼栋, 现网IP/VLAN/SVI, 目标IP/VLAN/SVI
  - DHCP, 端口/Trunk, 认证, 安全策略, 路由所有权
  - IPv6, 迁移批次, 验证项, 回退编号, 证据来源, 确认状态, 责任人
- **最少50条记录** (覆盖三校区主要业务)
- **编码规则**:
  - IP: 10.B.C.D (B = 区域码×10 + 业务码)
  - VLAN: 校区基数 + 业务偏移 (东100/西200/南300)
  - 楼栋: C = 楼栋序号×8 (/21块)

### Phase 5: 目标架构设计 (Status: pending)
- **输入**: IPAM源表 + 编码规则 + Phase 1决议
- **输出**:
  - 目标IP/VLAN设计 (成果#5)
  - 容量与安全闭合证明
- **包含**:
  - 每校区每业务的前缀、VLAN、SVI、DHCP、网关
  - SuperVLAN/Sub-VLAN或汇聚掩码结构
  - IPv6、路由、ACL/PBR联动
- **验证**:
  - 无IP重叠、VLAN无冲突
  - 容量3-5年充足
  - 设计闭环(IP→VLAN→SVI→DHCP→路由)

### Phase 6: 差异矩阵与配置增量 (Status: pending)
- **输入**: 现网基线 + 目标设计
- **输出**:
  - 逐对象差异矩阵 (成果#6)
  - 配置增量命令 (成果#7)
  - 批次规划与回退方案
- **分类**: A保留 / B适配 / C替换 / D清理 / V待验证
- **配置**:
  - RGOS命令(逐条带说明)
  - 中间状态检查点
  - 回退命令

### Phase 7-9: 验收与竣工 (Status: pending)
- **输出**:
  - 实验记录 (成果#8)
  - 部署文档 (成果#10)
  - 竣工报告 (成果#9)
