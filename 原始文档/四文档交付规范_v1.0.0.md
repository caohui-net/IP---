## 第3章：版本控制机制

### 3.1 版本号规则

**文档1（IPAM基线）**：
- 主版本号（X.0.0）：架构性变更（如新增校区、VLAN编码规则变更）
- 次版本号（x.Y.0）：功能性变更（如目标设计调整、容量规划修订）
- 修订号（x.y.Z）：数据修正（如现网数据更新、错误修正）

**文档2（设计方案）**：
- 主版本号（X.0.0-Final）：跟随文档1主版本号
- 后缀"-Final"表示该版本已通过评审
- 后缀"-Draft"表示草稿版本

**文档3/4（对照表/实施）**：
- 独立版本号（v1.0.0）
- 次版本号变更（v1.Y.0）：批次调整、步骤优化
- 修订号变更（v1.0.Z）：错误修正、格式调整

### 3.2 版本对应关系

| 发布批次 | 文档1版本 | 文档2版本 | 文档3版本 | 文档4版本 | 发布日期 |
|---------|----------|----------|----------|----------|---------|
| **第1批（当前）** | v2.0.0 | v2.0.0-Final | v1.0.0 | v1.0.0 | 2026-09-01 |
| 第2批（如需） | v2.0.1 | v2.0.1-Final | v1.0.1 | v1.0.1 | 待定 |

**版本更新触发条件**：
- 文档1更新（现网数据变化、目标设计调整）→ 文档2/3/4同步更新
- 文档2更新（设计决策调整）→ 文档1/3/4同步更新
- 文档3/4独立更新（批次调整、步骤优化）→ 不影响文档1/2，独立递增版本号

## 第4章：交叉引用规范

### 4.1 引用格式标准

**引用文档1的数据**：
```markdown
【格式】：根据文档1第X.Y节，{对象描述}（数据来源：文档1行NNNN-NNNN）。

【示例1】：
根据文档1第1.1.1节，南校区现网SuperVLAN 4001包含63个Sub-VLAN（3200-3262），
SVI配置为10.11.255.254/16（数据来源：文档1行98-100）。

【示例2】：
根据文档1第2.3.1节，南校区业务1目标SuperVLAN为1110，
IP段为10.31.0.0/16，容量余量306%（数据来源：文档1第3.2节容量汇总表）。
```

**引用文档2的决策**：
```markdown
【格式】：根据文档2决策N，{决策内容}。

【示例】：
根据文档2决策6，东校区业务3采用10.13.0.0/16设计，
Phase 0部署123个Sub-VLAN，剩余133个/24预留。
```

**引用文档3的映射关系**：
```markdown
【格式】：根据文档3第X.Y节，{映射关系描述}。

【示例】：
根据文档3第2.1节，南校区业务1的映射关系为：
现网4001/10.11 → 目标1110/10.31，映射类型为1:1，
迁移动作为SuperVLAN+IP段变更。
```

### 4.2 引用完整性检查

**发布前必检项**：
1. 所有引用的章节号必须存在于被引用文档
2. 所有引用的行号必须准确（允许±3行误差）
3. 所有引用的对象ID必须在被引用文档中唯一
4. 所有引用的数据必须与被引用文档一致

**检查工具**：
```bash
# 检查章节号引用
grep -rn "根据文档[1-4]第" *.md | while read line; do
  # 提取章节号并验证
done

# 检查行号引用
grep -rn "数据来源：文档[1-4]行" *.md | while read line; do
  # 提取行号并验证
done
```

## 第5章：数据一致性保证

### 5.1 单一事实来源（SSOT）原则

**文档1作为SSOT的对象**：
- VLAN编号和命名
- IP地址段和掩码
- 网关地址
- SuperVLAN和Sub-VLAN关系
- address-manage规则
- SVI配置
- 容量规划数据

**其他文档禁止独立定义的内容**：
- ❌ 文档2不得包含完整的VLAN/IP数据表（只能引用文档1）
- ❌ 文档3不得重新定义VLAN编号规则（只能引用文档1）
- ❌ 文档4不得修改网关地址（只能引用文档1）

### 5.2 数据一致性验证清单

| 验证项 | 验证方法 | 合格标准 | 不合格处理 |
|--------|---------|---------|-----------|
| 1. VLAN编号一致性 | 对比文档1第2章 vs 文档3第1.1节 | 所有VLAN编号完全一致 | 修正不一致项 |
| 2. IP地址段一致性 | 对比文档1第2章 vs 文档3第1.2节 | 所有IP地址段完全一致 | 修正不一致项 |
| 3. 网关地址一致性 | 对比文档1第2章 vs 文档4配置命令 | 所有网关地址完全一致 | 修正配置命令 |
| 4. SuperVLAN关系一致性 | 对比文档1第2章 vs 文档3第1.1节 | SuperVLAN和Sub-VLAN关系一致 | 修正关系 |
| 5. 容量数据一致性 | 对比文档1第3章 vs 文档2决策6 | 容量数字一致 | 修正计算错误 |
| 6. 批次依赖一致性 | 对比文档3第1.2节 vs 文档4第1.2节 | 批次依赖关系完全一致 | 修正依赖关系 |

## 第6章：变更管理流程

### 6.1 变更触发场景

**场景1：现网配置变化**
- 触发文档：文档1第1章（As-Is数据）
- 影响文档：文档3（新旧对照表现网列）、文档4（回退脚本）
- 变更流程：
  1. 更新文档1第1章
  2. 递增文档1修订号（v2.0.0 → v2.0.1）
  3. 同步更新文档3
  4. 同步更新文档4
  5. 文档2无需更新

**场景2：目标设计调整**
- 触发文档：文档1第2章（To-Be数据）
- 影响文档：文档2（设计决策）、文档3（新旧对照表目标列）、文档4（部署步骤）
- 变更流程：
  1. 更新文档1第2章
  2. 递增文档1次版本号（v2.0.0 → v2.1.0）
  3. 更新文档2第2章
  4. 同步更新文档3
  5. 同步更新文档4

**场景3：批次调整**
- 触发文档：文档3第1.2节（批次规划）
- 影响文档：文档4第1.2节（部署依赖矩阵）
- 变更流程：
  1. 更新文档3第1.2节
  2. 递增文档3修订号（v1.0.0 → v1.0.1）
  3. 同步更新文档4第1.2节
  4. 文档1/2无需更新

### 6.2 变更审批矩阵

| 变更类型 | 需要审批的文档 | 审批人 | 审批标准 |
|---------|---------------|--------|---------|
| 现网数据更新 | 文档1 | 网络运维负责人 | 与实际配置一致 |
| 目标设计调整 | 文档1、文档2 | 项目架构负责人 | 符合设计原则，无冲突 |
| 批次调整 | 文档3、文档4 | 迁移负责人 | 依赖关系合理，可回退 |
| 配置命令修正 | 文档4 | 实施负责人 | 语法正确，适配设备 |
